## Defects found

1. **AUTH-04: no logout control (BB-02).** No page or navigation offers logout or sign-out; the only way is `POST /api/v1/auth/logout`, which a user cannot reach from the UI. Steps: sign in as any role, then look at the header and every page.
2. **DON-01b: a donor cannot find their own donor profile ID (BB-06/07/08).** `/screening` and `/eligibility` require "Donor profile UUID", but registration only says "Account created. You can now sign in." and no page shows the ID. For this walkthrough the ID was read from the registration response in the browser's network data. Steps: register at `/register`, sign in, open `/screening`.
3. **AUTH-03 / REQ-08: the staff request page is not role-gated for requesters (BB-18 UI).** A signed-in requester opening `/staff/requests` sees their own requests with **Approve/Reject** controls (the shared `GET /api/v1/requests` returns their own list). Clicking Approve is refused by the server (403 "Your account is not permitted to review blood requests.") and the request stays Submitted, so this is a UI defect, not a security hole. Steps: as requester, submit a request, then open `/staff/requests`.
4. **Minor UX (not counted as FAIL): `/staff/inventory/new`** shows raw JSON after save or error ("Unit saved. {…}", "Unable to record unit. {…}") instead of a plain message (INV-01, INV-02).
5. **Operational note (not counted as FAIL): `evaluate_inventory_alerts` needs `--actor-id`;** a first run without it gave a usage error. With `--actor-id`/`--recipient-id` set to the staff account it created 32 LOW_STOCK alerts.
