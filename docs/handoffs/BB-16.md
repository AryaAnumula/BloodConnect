## Implemented

- **`POST /api/v1/requests/<uuid:request_id>/issues`** → 201 IssueResponse:
  - active non-superuser STAFF (`may_issue_requests` / `IsIssueStaff`) at both the API and the service; no clinical permission needed
  - session + CSRF, `StrictJSONParser`
  - body exactly `{"unit_ids": [...]}`: 1–100 canonical UUIDs; duplicates return 400
- **`issue_request(*, actor, request_id, unit_ids)`**, all in one atomic transaction:
  1. lock the request with `FOR NO KEY UPDATE`
  2. recheck APPROVED (else 422 `invalid_transition`)
  3. reject a batch above the remaining quantity (422 `oversupply`)
  4. take `issued_at` after the lock
  5. call `allocate_units` with sorted ids and the request's own group and component
  6. verify the DTOs exactly
  7. write issue records
  8. `fulfilled_quantity += n`: a partial batch stays APPROVED, exact completion becomes ISSUED

  Any failure rolls everything back.
- **Error mapping:**
  - provider `inventory.exceptions.UnitConflict` → 409 `unit_conflict`; `UnsafeUnit` → 422 `unsafe_unit`
  - DRF `APIException`s from the provider pass through unchanged
  - any other provider exception (including programming errors) is re-raised, never swallowed
  - `IntegrityError` → 409 `unit_conflict`; other `DatabaseError` → 503 `storage_unavailable`
- **Provider boundary** (`integrations/inventory.py`): imports at call time. A missing module (`inventory`, `inventory.services` or `.allocation`) → 503. A genuine import error inside the provider is re-raised.
- **`blood_requests.selectors.reporting.request_issue_totals(*, start=None, end=None)`** → `{"issued_unit_count": int}`:
  - both bounds None means all history
  - otherwise both must be aware datetimes with `start < end`, filtering the half-open interval `[start, end)` on `issued_at`
  - one-sided, naive, equal, reversed or non-datetime bounds raise `ValidationError`, with no fallback
  - sums actual `IssueRecord.issued_quantity`
  - Arya's `pending_request_count()` (from `team/arya-bb23`) is included unchanged in the same file; whichever branch merges second only needs the trivial combined file
- **Staff UI** (`/staff/requests`, Approved filter): "Issued X of Y" and an **Issue units** control. The client checks UUIDs, duplicates and the remaining count. It shows an honest 503 message, reloads on 409/422 conflicts and claims nothing before the server confirms.
- **OpenAPI:** `issueBloodUnits` stays `not_implemented`, with an implementation note; `IssueCreate.unit_ids` has `maxItems: 100`.
