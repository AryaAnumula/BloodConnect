## Implemented (request side)

- **`POST /api/v1/requests/<uuid:request_id>/issues`** (`api/issue.py`, `RequestIssueView`):
  - active non-superuser STAFF only (`may_issue_requests` / `IsIssueStaff`); no clinical permission needed
  - session + CSRF, `StrictJSONParser`
  - body exactly `{"unit_ids": [...]}`, 1–100 canonical UUIDs; duplicates in one payload return 400
  - returns 201 `IssueResponse`
- **`blood_requests.services.issue.issue_request(*, actor, request_id, unit_ids) -> dict`**, the public contract in `services.md`. Inside one `transaction.atomic`:
  1. lock the request with `select_for_update(no_key=True)`
  2. recheck APPROVED (else 422 `invalid_transition`)
  3. reject a batch above `quantity - fulfilled_quantity` (422 `oversupply`)
  4. take `issued_at` after the lock
  5. call `allocate_units(...)` with sorted unit ids and the request's own group and component
  6. verify the returned DTOs exactly (`checked_allocation`: same ids, UUID order, `quantity` int 1, no extra keys)
  7. write one issue record per unit
  8. `fulfilled_quantity += n`: a partial batch stays APPROVED; exact completion becomes ISSUED
- **Error mapping:** `IntegrityError` → 409 `unit_conflict`; other `DatabaseError` → 503 `storage_unavailable`; provider exceptions propagate unchanged; any failure rolls everything back.
- **Provider boundary** (`integrations/inventory.py`): imports Yashwitha's module at call time. If it's missing, 503 `inventory_unavailable`. A genuine import error inside an existing provider is re-raised, not hidden. `blood_requests` never defines its own allocation.
- **Issue-record writer** (`_write_issue_records`): looks up `blood_requests.IssueRecord` and fails closed (503) until that model exists.
- **Staff UI** (`/staff/requests`, Approved filter): each APPROVED row shows "Issued X of Y" and an "Issue units" control (unit IDs one per line). The client checks UUIDs, duplicates and the remaining count before sending. It shows an honest message for 503 (inventory not connected), reloads on 409/422 state conflicts, and claims nothing before the server confirms.
- **OpenAPI:** `issueBloodUnits` stays `not_implemented`, with an `x-implementation-note` describing this checkpoint; `IssueCreate.unit_ids` now has `maxItems: 100`.
