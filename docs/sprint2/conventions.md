# Sprint 2 shared conventions

Status: PROPOSED interfaces; existing session/CSRF, strict validation and privacy controls are retained, not redesigned. Existing versioned /api/v1 routes have no trailing slash. Current source main is recorded in README.

- JSON snake_case; UUID string IDs; account/profile/collection/unit IDs are distinct. No camelCase parallel fields. No client-supplied owner/role/state/expiry/fulfilled totals.
- Strict server validation of raw query parameters, unknown/read-only fields, duplicate keys, malformed/non-finite values and duplicate filters. Use existing core.validation/StrictJSONParser conventions, not blanket HTML escaping at storage. Optional field omitted differs from explicit null; schemas declare nullable when allowed.
- UTF-8 files; aware UTC response timestamps using RFC3339, Asia/Kolkata date semantics only where approved. Reject naive input datetime and starts_at>=ends_at. Evaluate one consistent clock snapshot per operation; inject clock in tests.
- Existing sessionid HttpOnly cookie; same-origin fetch credentials; unsafe requests need X-CSRFToken from /api/v1/auth/csrf. Shared frontend api client handles empty 204 and field errors. No JWT, React, CORS workaround or second auth stack.
- Keep current 401 invalid_credentials for login; Sprint 2 missing/expired session uses existing 403 authentication_required, authenticated wrong role 403 forbidden. Hidden foreign-owner record uses same 404 body as missing; applicable existing audit hook exactly once, not duplicate writes in permission and controller.
- Error envelope: error={code,message,fields:{field:[message]},request_id:UUID}; never raw database errors, payloads, tokens or donor-health answers. 400 invalid syntax/fields, 409 concurrent/duplicate/capacity/policy_unresolved, 422 unsafe/ineligible/invalid business transition, 503 redacted unavailable storage/service. New domain exceptions mapped centrally only in a coordinated narrow PR; do not swallow unknown errors.
- Lists {count,page,page_size,results}; page>=1, size1..100 default20, empty200/results[], no null list. Stable sort is operation-specific: UUID inventory; urgency rank/created_at/id requests; starts_at/id camps/slots/appointments. No unapproved arbitrary sort parameter.
- New routes are DESIGNS ONLY until implemented; no fake200/201. Do not mount endpoints from this documentation pack. If deliberately adding an honest stub later, document its actual501 instead of claiming success. OpenAPI x-implementation-status updated with evidence when implemented.
- Python modules import other modules’ public services/selectors; do not HTTP-call Django from Django. Frontend uses HTTP. Django→Node private authenticated HTTP with generated service token, bounded timeout; never browser session token or direct cross-language import.
- Raw clinical answers stay on existing donor-specific endpoints. Operational stock/request/report DTOs are minimized. No ADMIN/superuser shortcut to clinical data.
- All domain writes and durable intent insertions commit atomically; network delivery occurs after commit via retryable dispatcher. Failure after business commit does not roll back a valid blood issue/booking; pending/failed delivery remains visible.
- For mocks/tests: use contract DTOs at the boundary. Mock-based success is NOT integration proof. If provider not merged, finish independent UI/serializer/service logic, mark actual provider integration pending; do not copy another member’s model.
